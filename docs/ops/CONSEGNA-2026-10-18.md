### Ingressi e dipendenze

K00b introduce l'extra opzionale `media` con `pillow==13.0.0`, presente anche
in `dev`, e aggiorna `uv.lock`. Il motore senza foto non richiede Pillow;
senza decoder la foto viene rifiutata e l'ingresso manuale resta disponibile.
Limiti attuali: 2 MB, massimo 40 milioni di pixel e 10.000 per lato. Il digest
conserva i byte originali, compresi i metadati EXIF: non normalizza orientamento
o fedeltà della trascrizione. Nessuna foto reale o chiamata OCR è una prova di
questa consegna. Non cambiano licenze o notice della lavagna Excalidraw.

### Verificatore e copertura

Usare [ADR-GOV-CODEX-001](../decisions/ADR-GOV-CODEX-001.md) e
[decisione di copertura](../decisions/2026-10-18-coverage-ratchet.md).
Le ricevute richiedono una directory esterna nuova; report vecchi, alias,
symlink e antenati symlink vengono rifiutati. Una mutazione dei sorgenti
durante le verifiche invalida il risultato. Test falliti, tutti saltati o
evidenza mancante non producono `CHECKS_PASSED`.

Il timeout riguarda il gruppo iniziale dei processi. Un figlio che crea una
sessione autonoma può sopravvivere: `process_tree_isolation=false` è un limite
esplicito, aperto come `GOV-K-01/worker-isolation`. Questo comando non è una
sandbox per worker arbitrari e non seleziona da solo lavoro eleggibile.

La baseline resta 14.179/14.516 = 97,6784238082%; non è stata abbassata o
rigenerata per far passare il candidato. Il confronto usa conteggi interi.
Costituzione, definizione di Verified, holdout, privacy, cataloghi chiusi e
autorità dei generatori sono conservati. La FASE 1 generata non è stata
modificata a mano.

### Quaderni offline e contenuti DRAFT

Il campo opzionale `savedLesson` del quaderno `kirchhoff-portable-session.v3`
usa `kirchhoff-saved-lesson.v1` e lega con SHA-256 netlist, metodo richiesto,
risultato esatto, revisione del motore e vista salvata. Limite della vista:
4 MB. È integrità, non autenticità: il proprietario del file può ricalcolare
l'hash. Le versioni precedenti restano leggibili col server, senza aggiungere
approvazioni alla loro importazione.

`SavedNotebook.tsx` mostra circuito, passi, formule, risultato e storico grezzo;
non calcola né produce nuove diagnosi. La riapertura con server ricalcola come
prima. Errori HTTP 500/503 restano errori; assenza rete, 404 capability o HTML
statico con risposta riuscita consentono la copia in sola lettura. Chiuderla
invalida le richieste pendenti. I quaderni senza `savedLesson` richiedono ancora
il server. La scena libera si esporta in JSON ma **non è visualizzata offline**.

Il service worker conserva shell e asset dopo un primo accesso online in
contesto sicuro. Non mette API o quaderni nella cache. Il namespace comprende
lo scope e la revisione comprende i byte degli asset pubblici. Browser senza
supporto, cache cancellata e prima apertura completamente offline non sono
coperti da questa disponibilità. SVG e MathML mantengono la sanitizzazione
della superficie esistente.

API/MCP e ogni pagina PDF mostrano esplicitamente DRAFT. Sono stati rigenerati
18 JSON/PDF del catalogo: nei JSON cambiano soltanto `source_sha`, `lesson_build`
ed `editorial_status`; i corpi PDF sono uguali esclusi i footer. Lo SHA di base
registrato dal generatore non viene presentato come il futuro commit finale.
Vedere [ADR K05a](../decisions/ADR-K05A-OFFLINE-READER.md).

### Oracolo del partitore e percorso osservato

Caso sintetico originale: 12 V, R1=2 kΩ, R2=1 kΩ. Senza carico Vout=4 V;
con RL=1 kΩ, R2∥RL=500 Ω e Vout=12×500/2500=12/5 V; riferimento invertito
−12/5 V. Queste formule scalari non usano il solver per produrre l'atteso;
i metodi applicativi condividono comunque kernel/proiezioni e non sono oracoli
statisticamente indipendenti.

15 richieste HTTP: 14 accettate con quei risultati; Thévenin senza carico
correttamente non applicabile (422). Nel browser: valore 4 respinto sul
partitore caricato, lettura illeggibile non giudicata, 12/5 e −12/5 accettati;
quattro tentativi conservati nel JSON e PDF di nove pagine. Riapertura in
nuovo contesto online e pagina chiusa/nuova pagina offline riuscite; offline
zero richieste `/api/solve` e riesportazione JSON identica. Le immagini e il
PDF sono osservazioni delle 13:36–13:40 UTC, prima dell'ultimo rebuild del
catalogo; la suite finale delle 14:46–14:52 UTC è una prova separata.

Il controllo strutturato già presente rifiuta `serie R1 R2 3000` con RL,
perché `out` ha grado 3; l'illeggibile si astiene e `parallelo R2 RL 500`
seguito da `tensione R2 12/5` è valido fin lì. Dal solo valore numerico 4
non si inferisce che lo studente abbia dimenticato RL. Resta da completare

### Comandi per riprodurre le verifiche

Da un checkout del candidato, con Python 3.12/uv e Node 22 disponibili:

```bash
uv sync --frozen --extra dev --extra mcp
npm ci --prefix web
npm run build --prefix web
uv run --no-sync python scripts/bmad_chain.py verifica --con-loop
```

Scegliere un percorso **nuovo ed esterno al repository**; ad esempio, dopo
aver impostato `KIRCHHOFF_RUN` a una directory di lavoro esterna esistente:

```bash
./ops/loop/kirchhoff-loop verify --output "$KIRCHHOFF_RUN/python" --timeout 1800
npm run test --prefix web -- --maxWorkers=1
```

Eseguire in sequenza e congelare i sorgenti durante i gate. Il timeout 1800 s
è per comando, non budget totale. Per i browser avviare l'API posseduta senza
credenziali vision, in un terminale:

```bash
env -u OPENAI_API_KEY -u KIRCHHOFF_VISION_MODEL \
  uv run --no-sync python scripts/serve_student.py --port 43921
```

In un altro terminale da `web/`, con 4173 libera:

```bash
KIRCHHOFF_LIVE_BASE_URL=http://127.0.0.1:43921 npm run test:e2e -- --workers=2
```

Il run locale archiviato usava preview 43922 per evitare un server preesistente
su 4173; la configurazione esatta è nel pacchetto di evidenza. Configurare una
nuova output directory per ogni run, senza sovrascrivere ricevute. Gli output
di build sono ignorati; non rigenerare catalogo o baseline soltanto per ottenere
un verde. Fermare soltanto i processi avviati per quella verifica.

- Ruling: aggiungere `verify` al CLI vigente senza ritirarne l'autorità.
  Motivo: conservare i gate durante la migrazione; costo se errato: adozione
  ancora parziale e approvazione del processo necessaria.

  Motivo: evitare lavoro duplicato; costo se errato: occorre ricostruire la
  provenienza dai commit, che restano conservati.

  Motivo: il comando esegue gate noti, non worker arbitrari; costo se errato:
  processi autonomi possono sopravvivere. Non adottarlo come isolamento.

  senza promuovere `main`. `pubblica.sh` è main-only e non gestisce candidati:
  non viene modificato né forzato; costo se errato: serve un'integrazione
  successiva esplicita. L'anteprima lavagna non iniziata passa alla ripresa.

implementativo attivo, nessun monitor ricorrente creato. Checkout e archivio
